# 캐시 전략 가이드 (C-OSINE 프로젝트)

> **목적**: C-OSINE 프로젝트 전반의 캐시 계층 전략 통일

---

## 📊 캐시 계층 구조 (예시)

```
┌─────────────────────────────────────────┐
│  계층 1: 브라우저 메모리                   │
│  - Custom Client-side Cache Manager     │
│  - TTL: [예시: 5분]                      │
│  - 용도: 자주 접근하는 UI 데이터         │
└─────────────────────────────────────────┘
              ↓ 캐시 미스
┌─────────────────────────────────────────┐
│  계층 2: 백엔드 메모리                     │
│  - Redis 캐시 또는 인메모리 캐시          │
│  - TTL: [예시: 10분]                     │
│  - 용도: 사용자 세션, 자주 조회되는 API 결과│
└─────────────────────────────────────────┘
              ↓ 캐시 미스
┌─────────────────────────────────────────┐
│  계층 3: 데이터베이스                      │
│  - 영구 저장                             │
│  - 용도: 모든 영구 데이터                │
└─────────────────────────────────────────┘
```

---

## 🎯 계층별 역할 (예시)

| 계층 | 도구 | TTL | 최대 크기 | 용도 |
|------|------|-----|-----------|------|
| **L1 Frontend** | Custom Cache Manager | 5분 | 100개 | 사용자 설정, 임시 UI 상태 |
| **L2 Backend** | Redis / In-memory | 10분 | 무제한 | 인증 토큰, 임시 데이터 |
| **L3 DB** | PostgreSQL / MongoDB | 영구 | 무제한 | 핵심 비즈니스 데이터 |

---

## 📝 캐시 결정 플로우

```
데이터 조회 요청
   ↓
[Q1] 변경 빈도는?
   ├─ 거의 없음 (정적 데이터) → 프론트엔드 캐시 (L1)
   ├─ 가끔 (사용자 정보, 설정) → 백엔드 캐시 (L2)
   └─ 자주 (실시간 데이터) → 캐시 없이 DB 직접 조회
   ↓
[Q2] 재부팅 후 복구 필요?
   ├─ 예 → 데이터베이스 영구 저장 (L3)
   └─ 아니오 → 메모리만 사용 (L1, L2)
```

---

## 🔄 캐시 무효화 전략 (예시)

| 상황 | 전략 | 구현 |
|------|------|------|
| **데이터 변경(CRUD)** | 자동 무효화 | 백엔드 API 후처리, 프론트엔드 이벤트 |
| **사용자 정보 변경** | 수동 무효화 | 관련 서비스 로직에서 직접 처리 |
| **타임아웃** | TTL 기반 | 캐시 시스템 내 자동 만료 |
| **메모리 부족** | LRU / FIFO 제거 | 캐시 관리자 정책에 따름 |
