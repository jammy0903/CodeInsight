# Java 분석 도구: 메모리 뷰 vs. 흐름 뷰

Java 애플리케이션의 성능 문제를 진단할 때 사용되는 '메모리 뷰'와 '흐름 뷰'는 각기 다른 관점에서 문제를 바라보는 상호 보완적인 도구입니다.

### 1. 메모리 뷰 (Memory View): "무엇이 메모리를 차지하는가?"

메모리 뷰는 애플리케이션의 특정 시점 메모리 상태를 사진처럼 찍어 분석하는 **'정적' 관점**에 가깝습니다. 주로 **힙 덤프(Heap Dump)** 파일을 분석하여 메모리 누수나 비효율적인 메모리 사용의 원인을 찾는 데 집중합니다.

**주요 확인 항목:**

*   **객체 목록 (Object List)**: 현재 메모리에 존재하는 모든 객체의 리스트와 개수를 확인하여 비정상적인 객체 생성을 탐지합니다.
*   **Shallow Heap vs. Retained Heap**:
    *   **Shallow Heap**: 객체 자체가 차지하는 순수 메모리 크기.
    *   **Retained Heap**: 해당 객체가 사라졌을 때 함께 회수될 수 있는 모든 객체의 총메모리 크기. **메모리 누수 분석의 핵심 지표**입니다.
*   **지배자 트리 (Dominator Tree)**: 객체 간 참조 관계를 트리 구조로 시각화하여, 어떤 객체가 다른 객체들의 생존에 영향을 미치는지(지배하는지) 파악합니다.
*   **GC 루트 경로 (Path to GC Roots)**: 특정 객체가 왜 메모리에서 해제되지 않는지 그 참조 경로를 역추적하여 누수의 근본 원인을 찾습니다.

> **요약: 메모리 뷰는 '결과'를 보여줍니다. 즉, "현재 어떤 객체들이, 왜, 얼마만큼의 메모리를 점유하고 있는가?"에 대한 답을 제공합니다.**

### 2. 흐름 뷰 (Flow View / Execution View): "무엇이 시간을 잡아먹는가?"

흐름 뷰는 코드의 실행 과정과 스레드의 상태를 분석하는 **'동적' 관점**입니다. CPU 사용량, 메서드 실행 시간, 스레드 동작을 추적하여 성능 병목이나 시스템 멈춤 현상의 원인을 찾습니다.

**주요 확인 항목:**

*   **CPU 프로파일링 (CPU Profiling)**:
    *   **핫스팟 (Hotspots)**: CPU 시간을 가장 많이 소비하는 메서드를 찾아 성능 개선 대상을 식별합니다.
    *   **호출 트리 (Call Tree)**: 메서드 호출 순서와 각 단계의 소요 시간을 측정하여 비효율적인 코드 경로를 분석합니다.
    *   **플레임 그래프 (Flame Graph)**: 전체 호출 스택을 시각적으로 표현하여 병목 지점을 직관적으로 찾습니다. (그래프의 넓은 부분이 CPU 사용량이 많은 곳)
*   **스레드 분석 (Thread Analysis)**:
    *   **스레드 덤프 (Thread Dump)**: 특정 시점의 모든 스레드 상태와 실행 중인 코드 라인을 확인합니다.
    *   **스레드 상태 (Thread States)**: 스레드가 `RUNNABLE`(실행), `BLOCKED`(락 대기), `WAITING`(조건 대기) 중 어떤 상태인지 분석합니다. `BLOCKED` 상태의 스레드는 리소스 경합이나 데드락(Deadlock)의 단서가 될 수 있습니다.

> **요약: 흐름 뷰는 '과정'을 보여줍니다. 즉, "어떤 코드가, 왜, 얼마만큼의 시간을 사용하고 있는가?" 또는 "스레드들이 왜 멈춰있는가?"에 대한 답을 제공합니다.**

### 결론

일반적으로 애플리케이션이 느릴 때는 **흐름 뷰**로 병목 지점을 찾고, 메모리 사용량이 계속 증가하거나 `OutOfMemoryError`가 발생할 때는 **메모리 뷰**로 누수 원인을 찾는 것이 효율적인 접근 방식입니다.
