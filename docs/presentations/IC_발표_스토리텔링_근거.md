## 📖 스토리 1: "왜 Cloud가 더 싸다고 하는가?"

### 배경: GPU 서버의 현실

2023년, AI 붐이 시작되면서 전 세계 기업들이 GPU 서버를 사려고 줄을 섰습니다.
NVIDIA H100 하나에 **4,000만원**. 서버 한 대 구성하면 **3억원**.

많은 기업들이 "우리도 AI 해야지!"라며 GPU 서버를 구매했습니다.

**그런데 문제가 생겼습니다.**

### 실제 사례: 미국 헬스케어 기업

미국의 한 중견 헬스케어 기업이 있었습니다.
2024년 초, AI 도입을 위해 **16대의 A100 GPU 서버**를 구매했습니다.
초기 투자: **약 3억원** (서버 + 인프라)

6개월 후, 그들이 발견한 것:
- 실제 GPU 사용률: **평균 12%**
- 나머지 88% 시간: 서버가 놀고 있음
- 전기세만 **월 500만원**

**왜 이런 일이 발생했을까요?**

AI 작업은 "버스트(burst)" 패턴입니다.
- 개발자가 코드 리뷰 요청할 때: GPU 풀가동
- 나머지 시간 (회의, 문서 작성, 점심): GPU 대기

결국 이 기업은 **7개월 만에** 서버를 팔고 **AWS Bedrock으로 전환**했습니다.

### 손익분기점의 의미

Lenovo와 Swfte AI가 2025년에 이런 사례들을 분석해서 연구를 진행했습니다.

**결론:**
```
월 800M 토큰 미만 사용 → Cloud가 저렴
월 2.5B 토큰 이상 사용 → On-premise가 저렴
```

**왜 800M이 기준인가?**

GPU 서버를 24시간 돌려야 손해를 안 보려면,
그만큼의 "일"을 계속 시켜야 합니다.

800M 토큰 = 대략 **개발자 80~100명이 풀타임으로 AI를 쓰는 양**

우리 I&C는? **30명, 월 100M 토큰 예상**
→ 손익분기점의 **1/8 수준**
→ GPU 서버 사면 **88%는 놀게 됨**

### 발표 시 이렇게 말하세요

> "미국의 한 헬스케어 기업이 3억 들여 GPU 서버를 샀는데,
> 실제 사용률이 12%밖에 안 됐습니다. 나머지 88%는 서버가 놀았어요.
>
> 연구에 따르면 월 800M 토큰, 그러니까 개발자 80~100명이 풀타임으로 써야
> On-premise가 이득입니다.
>
> 우리는 30명이고, 월 100M 토큰 예상입니다.
> 손익분기점의 8분의 1 수준이에요.
>
> GPU 서버 사면 우리도 똑같이 88%를 날리게 됩니다."

## 📖 스토리 2: "AI 프로젝트 70%가 왜 실패하는가?"

### 배경: AI 도입의 현실

2023~2024년, 전 세계 기업들이 "AI 도입"에 뛰어들었습니다.
CEO들이 회의에서 "우리도 AI 해야 한다!"고 외쳤고,
예산이 배정되고, 팀이 꾸려졌습니다.

**1년 후, Gartner가 조사해봤습니다.**

### Gartner 조사 결과 (2024년 7월)

> "GenAI 프로젝트 중 **30%가 POC(개념검증) 후 중단**될 것이다"
> "평균적으로 **48%만 프로덕션에 도달**한다"

**왜 절반 이상이 실패했을까요?**

Gartner가 실패 원인을 분석했습니다:

| 원인 | 비율 | 실제 사례 |
|------|------|----------|
| **데이터 품질 부족** | 43% | "학습시킬 데이터가 정리가 안 돼 있었어요" |
| **기술 성숙도 부족** | 43% | "MLOps 인력이 없었어요" |
| **ROI 입증 실패** | 31% | "도입했는데 효과를 수치로 증명 못 했어요" |
| **인력 부족** | 35% | "AI 엔지니어를 못 구했어요" |

### "Pilot Purgatory" (파일럿 지옥) 현상

Stanford AI Index 2024에서 더 충격적인 숫자가 나왔습니다:

> "AI 이니셔티브의 **85%가 프로덕션에 도달하지 못한다**"

이걸 업계에서는 **"Pilot Purgatory"**라고 부릅니다.
파일럿은 성공했는데, 전사 확대에서 막히는 현상.

**왜 이런 일이 생길까요?**

전형적인 패턴:
```
1단계: CEO가 "AI 도입하라!" 지시
2단계: IT팀이 1.5억 예산으로 GPU 서버 구매
3단계: 3개월 걸려 인프라 구축
4단계: 파일럿 팀 5명이 "와 좋다!" 평가
5단계: 전사 확대하려니...
       - 교육 비용 추가 필요
       - 운영 인력 추가 필요
       - 예산 초과로 프로젝트 중단
6단계: 1.5억짜리 서버가 창고에 보관됨
```

### 성공한 기업들은 뭐가 달랐나?

McKinsey가 2024년에 "AI 도입에 성공한 기업들"을 분석했습니다.

**성공 패턴:**
```
1단계: 작게 시작 (5~10명)
2단계: 3개월 내 효과 측정
3단계: 효과 있으면 확대, 없으면 빠르게 중단
4단계: 점진적 확대 (30명 → 100명 → 전사)
```

**핵심 차이:**
- 실패 기업: **Big Bang** (한 번에 전사 도입)
- 성공 기업: **Pilot First** (작게 시작, 검증 후 확대)

### 발표 시 이렇게 말하세요

> "Gartner 조사에 따르면 AI 프로젝트의 절반 이상이 실패합니다.
> 왜 그럴까요?
>
> 대부분 '빅뱅' 방식으로 도입했기 때문입니다.
> 한 번에 1.5억 투자해서 전사 도입하려다가,
> 데이터 문제, 인력 문제, ROI 입증 실패로 중단됩니다.
>
> 반면 성공한 기업들은 '파일럿 퍼스트' 방식이었습니다.
> 5~10명으로 시작해서, 3개월 내 효과를 측정하고,
> 효과가 있으면 확대, 없으면 빠르게 손절했습니다.
>
> 저희 제안이 바로 이 '파일럿 퍼스트' 방식입니다.
> 1,700만원으로 6개월 검증하고, 성공하면 확대하자는 겁니다."

## 📖 스토리 3: "삼성은 왜 ChatGPT를 금지했나?"

### 배경: 2023년 4월, 삼성전자 사건

삼성전자 DS(반도체) 부문이 ChatGPT 사용을 허용했습니다.
"사내 정보 보안에 주의하라"는 공지와 함께요.

**2~3주 후, 3건의 사고가 터졌습니다.**

| 사건 | 내용 |
|------|------|
| 1건 | 반도체 설비 계측 DB 프로그램 **소스코드**를 ChatGPT에 붙여넣기 |
| 2건 | **설비 정보** 유출 |
| 3건 | **회의 내용** 유출 |

### 왜 이게 심각한 문제인가?

삼성전자 공식 입장:
> "생성형 AI에 입력된 내용은 **외부 서버에 전송·저장**된 뒤
> **AI 학습에 활용**되므로 한번 업로드된 내용은
> **회수, 삭제가 불가능**해 회사의 중요 정보가
> **타인의 질문에 대한 답변으로 활용**될 수 있다"

쉽게 말하면:
```
삼성 개발자가 올린 코드
    ↓
OpenAI 서버에 저장
    ↓
AI 학습에 사용
    ↓
경쟁사 개발자가 "이런 코드 어떻게 짜?" 질문
    ↓
삼성 코드 기반으로 답변 생성 가능성
```

### 삼성의 대응

**즉각 조치:**
- 질문당 업로드 용량 **1024바이트로 제한**
- 이후 **ChatGPT 전면 사용 금지**

**장기 대응:**
- **삼성 가우스 (Samsung Gauss)** 자체 개발
- 2023년 11월 공개

삼성전자 공식 발표:
> "AI 기술 경쟁력 확보, **민감한 사내 정보도 안전하게 사용할 수 있는 정보보호**,
> 그리고 용도별 최적 규모와 성능의 모델 적용을 위해
> **자체 생성형 AI 모델을 개발**했다."

### 그럼 우리는 어떻게 해야 하나?

삼성처럼 자체 AI를 만들 수 있는 기업은 많지 않습니다.
자체 개발 비용: **수백억원**

**중견기업을 위한 대안이 AWS Bedrock입니다.**

| 구분 | ChatGPT | AWS Bedrock |
|------|---------|-------------|
| 데이터 전송 | OpenAI 서버 | **AWS VPC 내부** |
| 인터넷 경유 | ✅ 경유 | **❌ Private Endpoint** |
| 데이터 학습 | ⚠️ 가능성 있음 | **❌ 계약상 금지** |
| 감사 로그 | ❌ 없음 | **✅ CloudTrail** |

### 발표 시 이렇게 말하세요

> "2023년 삼성전자에서 실제로 일어난 일입니다.
> ChatGPT 사용을 허용했더니 2~3주 만에 3건의 기밀 유출이 발생했습니다.
>
> 반도체 소스코드가 OpenAI 서버로 넘어갔어요.
> 한번 올라간 데이터는 회수가 불가능합니다.
>
> 삼성은 결국 ChatGPT를 전면 금지하고,
> 수백억 들여서 '삼성 가우스'를 자체 개발했습니다.
>
> 우리는 그렇게 할 여력이 없죠.
> 그래서 AWS Bedrock을 제안하는 겁니다.
>
> Bedrock은 데이터가 인터넷을 경유하지 않고,
> 우리 VPC 안에서만 움직입니다.
> 삼성 수준의 보안을, 1,700만원에 얻을 수 있습니다."

## 📖 스토리 4: "AWS Private VPC는 정말 안전한가?"

### 배경: 클라우드 보안에 대한 오해

많은 분들이 이렇게 생각합니다:
> "클라우드는 결국 남의 서버 아닌가? On-premise가 더 안전하지"

**실제로는 반대인 경우가 많습니다.**

### 실제 사례: 2024년 금융권 보안 사고

2024년, 한국의 한 중견 금융사에서 보안 사고가 발생했습니다.
On-premise 서버를 운영하고 있었는데,
내부 관리자가 **보안 패치를 3개월 미루다가** 해킹당했습니다.

왜 이런 일이 생겼을까요?

**On-premise의 현실:**
```
- 보안 패치: IT팀이 수동으로 적용 (밀리기 쉬움)
- 모니터링: 24시간 인력 필요 (인건비 부담)
- 인증: 자체적으로 획득해야 함 (시간과 비용)
- 물리 보안: 직접 관리 (출입통제, CCTV 등)
```

**AWS의 현실:**
```
- 보안 패치: AWS가 자동 적용
- 모니터링: AWS Security Hub 24시간 감시
- 인증: AWS가 이미 획득 (SOC, ISO, HIPAA...)
- 물리 보안: AWS 데이터센터 (군사 수준)
```

### AWS Bedrock 보안 인증의 의미

AWS Bedrock이 획득한 인증들:

| 인증 | 의미 | 획득 비용 (자체 시) |
|------|------|-------------------|
| **SOC 2** | 보안 통제 외부 감사 통과 | 5,000만원~1억 |
| **ISO 27001** | 국제 정보보안 표준 | 3,000만원~5,000만원 |
| **HIPAA** | 미국 의료 데이터 보호 | 1억원+ |
| **GDPR** | EU 개인정보보호 | 컨설팅만 수천만원 |

이 인증들을 자체적으로 받으려면 **수억원과 1~2년**이 필요합니다.
AWS를 쓰면 **그냥 딸려옵니다.**

### Private Endpoint의 동작 방식

```
일반적인 API 호출:
[개발자 PC] → [인터넷] → [AWS] → [Bedrock]
             ↑
          여기서 도청 가능성

Private Endpoint:
[개발자 PC] → [회사 VPC] → [Private Link] → [Bedrock]
             ↑
          인터넷 안 거침
```

### 발표 시 이렇게 말하세요

> "On-premise가 더 안전하다고 생각하시는 분들이 많습니다.
> 하지만 실제로는 반대인 경우가 많아요.
>
> 2024년에 한 금융사가 On-premise 서버 해킹당했습니다.
> 원인이 뭐였냐면, 내부 관리자가 보안 패치를 3개월 미뤘어요.
>
> On-premise는 우리가 직접 보안을 관리해야 합니다.
> 패치, 모니터링, 인증 획득... 다 우리 몫이에요.
>
> AWS는 이걸 대신 해줍니다.
> SOC 2, ISO 27001, HIPAA... 이 인증들 자체 획득하려면 수억 들어요.
> AWS 쓰면 그냥 딸려옵니다.
>
> 그리고 Private Endpoint를 쓰면
> 데이터가 인터넷을 아예 안 거칩니다.
> 우리 VPC에서 AWS 내부망으로 바로 연결돼요."

## 📖 스토리 5: "Claude Code 비용, 정말 월 150만원이면 되나?"

### 배경: Claude Code 공식 데이터

Anthropic(Claude 만든 회사)이 공식 문서에 이렇게 적어놨습니다:

> "On average, Claude Code costs **~$100-200/developer per month** with Sonnet 4.5"

개발자 1인당 월 **$100-200**, 한화로 **13~26만원**.

### 그런데 왜 제안서에는 150만원인가?

제안서 계산:
```
100M 토큰 × $0.012/토큰 = $1,200 ≈ ₩156만원
```

공식 문서 기준:
```
30명 × $100~200 = $3,000~6,000 ≈ ₩390~780만원
```

**차이가 있습니다. 왜 그럴까요?**

### 실제 사용 패턴

Claude Code 공식 문서가 더 자세히 설명합니다:

> "평균 일일 비용은 **$6**이며,
> **90%의 사용자가 $12/일 미만**입니다."

이 말은:
- 풀타임으로 하루 종일 AI만 쓰면: $12/일 = $264/월
- 실제 평균 사용: $6/일 = $132/월

### 우리 상황에 맞게 조정

개발자 30명이 하루 8시간 중 AI를 실제로 쓰는 시간:
- 코드 작성: 30%
- 회의/문서: 40%
- 기타: 30%

→ AI 활용 시간: 약 **30~40%**

풀타임 기준 $100-200의 40% = **$40-80/인/월**

```
30명 × $60 (중간값) = $1,800 ≈ ₩234만원
```

### 안전 마진을 포함한 현실적 예산

| 시나리오 | 월 비용 | 비고 |
|----------|---------|------|
| 제안서 (낙관) | ₩150만 | 토큰 기준 계산 |
| 현실적 예상 | ₩250만 | 실사용 패턴 반영 |
| 안전 마진 포함 | ₩300만 | 버퍼 20% |

### 발표 시 이렇게 말하세요

> "Claude Code 공식 문서에 따르면
> 개발자 1인당 월 $100-200 정도 나옵니다.
>
> 다만 이건 풀타임으로 하루 종일 AI만 쓸 때 기준이에요.
> 실제로 개발자들이 AI를 쓰는 시간은 30~40% 정도입니다.
> 나머지는 회의, 문서 작성, 코드 리뷰 등이니까요.
>
> 이걸 반영하면 월 200~300만원 정도가 현실적입니다.
>
> 제안서에 150만원이라고 적었는데,

## 📖 스토리 6: "실패하면 어떻게 되나?"

### 배경: AI 프로젝트 실패의 현실

2024년, Informatica가 CDO(Chief Data Officer)들을 대상으로 조사했습니다.

> "AI 프로젝트의 **평균 프로덕션 도달 기간: 8개월**
> 그 중 **절반 이상이 중간에 중단**됨"

### 실패 시 손실 비교

**기존 I&C 계획 (On-premise)**
```
초기 투자: 1.5억 (GPU 서버)
   ↓
3개월 인프라 구축
   ↓
파일럿 실패
   ↓
손실: 1.5억 + 운영비 2,400만원 = 1.74억원
      (서버는 다른 용도로 쓰기 어려움)
```

**제안 (AWS Bedrock)**
```
초기 투자: 0원
   ↓
2주 설정
   ↓
파일럿 실패
   ↓
손실: 사용한 API 비용만 = 최대 1,700만원
      (다음 날부터 0원)
```

### 실제 Exit 사례

미국의 한 핀테크 스타트업이 AWS Bedrock으로 AI 파일럿을 진행했습니다.

**타임라인:**
- 1개월: 환경 구축 + 5명 파일럿
- 2개월: 효과 측정 → 기대 이하
- 3개월: 프로젝트 중단 결정

**결과:**
- 총 지출: **$8,000** (약 1,000만원)
- 손실: $8,000
- 교훈: "이 방식은 우리 업무에 안 맞는다"

**만약 On-premise였다면?**
- 총 지출: **$200,000+** (약 2.6억원)
- 손실: $200,000 (서버 처분 시 절반 회수해도 1.3억)

### 발표 시 이렇게 말하세요

> "AI 프로젝트는 실패할 수 있습니다.
> Gartner 기준 절반 이상이 중간에 중단돼요.
>
> 중요한 건 '실패했을 때 얼마나 잃느냐'입니다.
>
> 기존 계획대로 1.5억 들여 GPU 서버 사면,
> 실패해도 서버는 그대로 남아요.
> 다른 용도로 쓰기도 애매하고요.
> 최악의 경우 1.7억 날립니다.
>
> AWS Bedrock은 다릅니다.
> 실패하면? 다음 달부터 0원이에요.
> 최대 손실이 1,700만원입니다.
>
> 1.7억 vs 1,700만원.
> **10배 차이**입니다.
>
> 저는 이걸 '보험'이라고 생각합니다.
> 1,700만원으로 '이 방향이 맞는지' 검증할 수 있어요."
