# Refactoring Checklist

## 기능 변경 시 필수 프로세스

### 1단계: 한 발짝 물러서서 전체 보기
- [ ] 폴더 구조와 설계 문서(`docs/architecture/`) 확인
- [ ] 변경하려는 기능이 계획된 디자인 설계에 맞는지 검토
- [ ] 관련된 모든 파일 파악 (컴포넌트, 훅, 타입, CSS)

### 2단계: 구조 및 재사용성 검토
- [ ] 폴더 구조 변경 필요 여부 판단
- [ ] 공통 유틸리티로 분리할 수 있는 코드 식별
- [ ] 함수 재사용성 최대화 방안 검토
- [ ] 공통 함수는 `func_index` 또는 `utils/index.ts`에 저장

### 3단계: 삭제 후 추가 (순서 엄수)
```
1. CSS 삭제 → 확인
2. 기능(함수/컴포넌트) 삭제 → 확인
3. Dead code/import 정리 → 확인
4. 새 기능 함수 적용
5. 새 CSS 적용
```

**중요**: 각 단계에서 삭제가 완전히 확인된 후에만 다음 단계로 진행

### 4단계: 검증
- [ ] TypeScript 컴파일 확인 (`npx tsc --noEmit`)
- [ ] 브라우저에서 실제 동작 확인
- [ ] 관련 테스트 통과 확인

---

## Dead Code 처리 원칙

1. **발견 즉시 삭제**: deprecated, unused 코드는 바로 삭제
2. **import 정리**: 삭제한 파일을 import하는 곳 모두 정리
3. **타입 정리**: 사용하지 않는 타입 export 제거

---

## Checklist (기존)
- [ ] 기존 테스트 통과 확인
- [ ] 코드 리뷰 완료
- [ ] 문서 업데이트
