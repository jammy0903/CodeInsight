## 2. 제품 브랜드: StarARC™

### 슬로건
> "반도체 회사가 만드는 아크 차단기"

### 제품 카테고리
- **AFDD** (Arc Fault Detection Device) - 아크 결함 감지 장치
- **AFCI** (Arc Fault Circuit Interrupters) - 아크 결함 회로 차단기

## 3. 핵심 기술 특징

### 3.1 인증 및 표준

| 인증/표준 | 상태 | 비고 |
|-----------|------|------|
| **KS C IEC 62606** | ✅ 인증 | 업계 유일 **11개 항목 완벽 인증** |
| **UL 1699** | ✅ 인증 | 미국 표준 |
| **KFI015** | ✅ 인증 | 한국소방산업기술원 |
| **전기안전공사기준** | ✅ 통과 | ARC 시험장치 |
| **KC, EMC** | ✅ 인증 | 전자파 적합성 |
| **품질인증** | ✅ 보유 | ISO 등 |
| **아크 시험성적서** | ✅ 보유 | |

### 3.2 IoT Platform 기반

- **통신 방식**: Wi-Fi, Ethernet, LTE 연동
- **다양한 설치환경** 지원
- **실시간 모니터링**: Dashboard / Mobile 지원

### 3.3 블랙박스 기능 ⭐ (데이터 분석 핵심!)

> **"실시간 아크 신호분석(전류/주파수)"**
> **"아크로 인한 차단기 트립 시 원인 분석가능"**

#### 의미
- 이미 전류(irms)와 주파수(freq) 데이터를 수집/분석 중
- 트립 원인 분석 기능 → 추가 데이터 수집 가능성 시사
- 현재 MQTT로 전송되는 `irms`, `freq` 배열이 이 기능의 일부

### 3.4 최적화 기능

> **"디버깅포트 노출 설계로 설치 후에도 현장에 최적화된 아크 펌웨어 업데이트 가능"**

#### 의미
- 펌웨어 업데이트로 추가 데이터 항목 수집 가능
- `trip_time_ms`, `arc_duration_ms`, `pre_fault_buffer` 등 추가 요청 근거

### 3.5 유지보수

- 한국전력공사 2천만호 원격검침시스템(AMI)의 주관사
- 자체유지보수 전담 팀 운영

```
[분전반]
    │
    ├── RS-485 Communications
    │
    ▼
[StarARC Connected]
    │
    ├── Wi-Fi & LTE & Ethernet
    │
    ▼
[Cloud]
    │
    ▼
[Mobile APP]
    ├── ARC 모니터링
    ├── Voltage 모니터링
    └── Current 모니터링
```

### 6.2 산업용 제품 구성

```
[산업 설비]
    │
    ├── Wi-Fi & LTE & Ethernet
    │
    ▼
[Cloud]
    │
    ▼
[관리자]
    └── Mobile APP (ARC, Voltage, Current)
```

### 6.3 StarARC IoT System (현재 대시보드 연동)

```
[StarARC Connected]
    │
    ├── RS-485통신
    │
    ▼
[485통신] ──► [TCP/IP] ──► [Wi-Fi & Ethernet/LTE]
                                    │
                                    ▼
                            [Server (or Cloud)]
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
              [Star ARC        [Network]      [원격관제실]
               Dashboard]                        │
                                                 ▼
                                              [kakao]
```

#### IoT System 기능
- RS-485통신 및 Gateway 연동(외부통신)
- 누전, 과전류, 아크센서 데이터 전송
- StarARC series 호환사용 가능
- 데쉬보드 모니터링

## 8. 데이터 분석 관점 핵심 정리

### 8.1 동작시간 분석

| 구분 | 시간 | 비고 |
|------|------|------|
| **누전시 동작시간** | 0.03sec (30ms) | ✅ 카탈로그 명시 |
| **아크 감지→트립 시간** | ❓ 미명시 | ⚠️ 추가 확인 필요 |
| **IEC 62606 요구사항** | 120ms 이내 | 표준 기준 |

#### ⚠️ 중요 발견
카탈로그의 "동작시간 0.03sec"는 **누전시** 동작시간!
**아크 감지 후 트립까지의 시간은 별도 명시되어 있지 않음**
→ `trip_time_ms` 데이터 요청의 근거

### 8.2 현재 수집 중인 데이터 (MQTT)

```json
{
  "header": {"op": "fault", ...},
  "data": {
    "faultType": "7",
    "irms": "0,0,0,...(30개)",      // 전류 샘플
    "freq": "0,0,0,...(30개)",      // 주파수 샘플
    "irmsAmpere": "0",
    "freqArcCnt": "0",
    "irmsArcCnt": "0",
    "carbonArcCnt": "0"
  }
}
```

### 8.3 추가 요청 필요 데이터

| 항목 | 필요 이유 | 기술적 가능성 |
|------|----------|--------------|
| `trip_time_ms` | 아크 감지→트립 시간 | ✅ 블랙박스 기능 존재 |
| `arc_duration_ms` | 아크 지속 시간 | ✅ 신호분석 기능 존재 |
| `arc_energy` 또는 voltage 샘플 | 에너지 계산 | ⚠️ 확인 필요 |
| `pre_fault_buffer` | 아크 발생 전 데이터 | ⚠️ 버퍼 구현 여부 확인 |
| `devType` 정의 | 모델/용량 구분 | ✅ 이미 전송 중 |
| `irms`/`freq` 샘플링 간격 | 시간축 분석 | ❓ 미확인 |

### 8.4 제품 모델별 ID 추정 (MQTT src 필드)

| src 접두사 | 추정 의미 |
|------------|----------|
| `IGWP...` | IoT Gateway Product? |
